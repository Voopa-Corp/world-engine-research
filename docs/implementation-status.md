# Implementation status

This document distinguishes engineering existence from simulation and empirical validation. The terms are deliberately narrow:

- **Implemented** means that the software object, relationship, or execution path exists in the inspected prototype.
- **Simulated** means that behavior follows explicit assumptions that can be exercised and inspected.
- **Proposed** means that a learning, inference, or evaluation mechanism remains to be trained or tested prospectively.

## Scientific boundary

The prototype establishes that the representational hierarchy can be implemented as an operating environment. It does not establish that the hierarchy is the uniquely correct decomposition of behavior, that it reads private mental states, or that it improves engagement, satisfaction, commercial performance, or well-being.

Human claims require prospective comparison with strong baselines, preregistered outcomes where appropriate, exposure correction, randomized interventions when lawful and safe, uncertainty reporting, and explicit failure criteria.
